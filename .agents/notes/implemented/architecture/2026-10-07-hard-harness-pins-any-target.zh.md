# Agent Note: hard harness 通过自有快照固定任意目标

Status: implemented

[English](2026-10-07-hard-harness-pins-any-target.md) | 中文

## 问题

hard harness 必须审计交给它的任何东西：git 仓库、没有 git 的源码目录，或单个共享库。武装时固定的是目标自身 git 中的提交，因此任何不是 git 仓库的目标都会加载失败，而首次武装会拒绝与提交不一致的工作区。

共用实时目标也破坏了独立读者。在第二次 pilot 中，三个读者都打开了目标未跟踪的 `poc/` 目录下任务 agent 的 PoC，其中携带它的发现主张；一个读者还在判定中按名称引用了某个 PoC。污染检查接受目标内的每一次读取，因此三次都没有被作废。

## 决策

- **固定提交是 harness 自有的快照。** 加载时，`hard-mission` 通过每次捕获私有的 index，把目标捕获进 `<target.snapshotRoot>/store.git`，这是位于目标之外的 git 目录（默认在 DSH home 下的 `hard/snapshots`）。git 工作树贡献其已跟踪文件以及忽略规则保留的未跟踪文件，内容取自工作区；普通目录贡献其忽略文件保留的每个文件；单个文件只贡献它自己。harness 的状态目录与目标的 `.git` 从不进入，目标内部不会写入任何内容。固定的身份与时间使提交只由内容决定，因此一个存储服务所有目标，并由 ref 让每个快照提交保持存活。
- **武装记录指明快照。** `hard/mission/armed` 在 `commit` 中保存快照提交，并新增 `snapshot`：存储位置、目标类型，以及 git 目标的 HEAD 与工作区是否不同。`pinnedGitArgs` 把它转换为每个读取固定内容的读取方所用的 git 参数；没有快照的记录继续读取目标自身的 git。
- **快照就是模型看到的内容。** 未提交的改动会被捕获而不是被拒绝，模型之后写入的文件都在快照之外。`target.commit` 只保留为可选检查：git 目标必须检出该提交。
- **读者读取快照的 worktree。** 每次读取前，`hard-audit` 把固定提交检出到新的临时 worktree，并通过 subagent 接缝新增的 `cwd` 选项在其中启动读者；spawn provider 支持该选项，其他 provider 会拒绝。除读者自己的 spill 文件外，worktree 之外的任何读取都是污染。读取前后的偏离检查已移除，因为 worktree 不会偏离。

## 考虑过的替代方案

- **继续要求 git 仓库。** 被否决：harness 必须像接受仓库一样接受反编译出的目录树、发布压缩包或单个二进制文件。
- **首次武装时拒绝偏离的工作区。** 已被取代：它防止提交包含模型从未看到的内容，而快照通过精确捕获模型所见实现了这一点。
- **把 PoC 移到目标之外。** 被否决：PoC 契约从目标根目录运行 PoC，而读者仍会共享实时工作树之后的每次修改。
- **每个目标路径一个存储。** 被否决：由路径派生的键在不同机器与临时目录间不同，而按内容寻址的提交不会。
- **为读者提供限制读取的文件系统。** 仍然暂缓：有了洁净的 worktree，worktree 之外的读取可以按路径检测，而影子测量只需要将其作废。

## 后果

- 普通目录与单个文件都能武装；在二进制路线按符号拆分之前，单个二进制文件只是一个不可筛查的行。
- 每次加载都会重新捕获目标，存储随每个不同的快照增长；相同文件只存储一次。
- 独立读者看到的恰好是武装时的内容，其污染规则收缩为单一根目录。
- subagent 接缝新增一项默认缺省的能力，因此现有 provider 无需改动。
